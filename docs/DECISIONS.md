## Backend

- **Extra commands:** `preview_rename` (counts the links for the "Update N links in M notes?" dialog), `reveal_in_file_manager` and `open_attachment` (OS integration through the Rust side of `tauri-plugin-opener`, so no filesystem scope has to be granted to the webview), `finish_close` (frontend → backend part of the window-close handshake).
- **`apply_proposals` takes a third argument** `confirmedChangedIds` and `ApplyResult` has `appliedIds`. The spec requires re-confirmation of files that changed after the proposal; the backend must know which ones the user confirmed. Proposal sets stay available after a partial apply so skipped files can be retried.
- **Extra pre-rename snapshot commit** (`Snapshot before rename: <path>`, only when something is uncommitted). Rewriting links changes other notes, so unsaved work in them is committed first (Core principle 1). A rename of a clean vault still creates exactly one commit.
- **Commit messages** follow the spec table exactly; `Rename`, `Delete` and `Restore` have no colon, as written in the spec.
- **Atomic writes:** notes are written to a hidden temp file in the same folder and renamed over the target.
- **Search index extras:** `notes_fts` rows use the `notes` row id so updates do not scan the table; extra indexes on `links(src)` and `tags(path)`. Backlinks are resolved at query time (not only from the stored `target_path`), so links to notes created or renamed later are still found.
- **Link rewriting** covers wiki-links and embeds (the syntax defined in §8.5). Standard Markdown links to notes (`[x](note.md)`) are not rewritten in v1.
- **Link resolution is implemented twice** (Rust `links::resolve` for indexing/rename, TypeScript `lib/links.ts` for synchronous styling in the editor). Both follow §8.5 and have tests.
- **Watcher:** every change (including Mimer's own writes) is reported; the editor ignores events whose content equals what it last wrote/read. A moved or removed folder triggers an incremental index sync.
- **Windows paths:** `canonicalize` returns `\\?\C:\…`; the prefix is removed from the path returned to the frontend so asset URLs and the recent-vault list use normal paths.
- **Local-only enforcement (replaced in 0.7.0, see below):** `ai::providers::chat` accepts only an approved provider (a `LocalProvider` or Raven's `CloudProvider`), created only by `ai::router`. Provider location is recomputed from the URL (a non-loopback `openai_compatible` URL is cloud even if the file says "local"). `list_models` / `test_provider` are settings-level calls and are not project-bound.
- **`regex` / `Regex::new(...).expect(...)`** appears only for fixed pattern literals in `LazyLock` statics (cannot fail at runtime); everything else returns `Result`.
- **Agent history:** only the visible user/assistant text is sent with each turn; tool calls from earlier turns are not replayed.

## Frontend

- **Live preview uses a CodeMirror `StateField`** instead of `ViewPlugin`s: block decorations (collapsed frontmatter) must come from a state field. The code is organised as the spec's `extensions/` files (`livePreview`, `wikiLinks`, `tags`, `images`, `pasteImage`).
- **Images** are shown in place of the Markdown (inline replace widget with `display: block`) rather than as a separate widget below the line.
- **Checkbox widgets** are shown on every line (including the cursor line) so they stay clickable.
- **Right-click → AI** opens the same popup as `Mod+K` when text is selected (the native context menu is replaced for selections).
- **Window close:** the backend prevents the close, emits `app://close-requested`, the frontend flushes its pending write and calls `finish_close`; if the frontend does not answer within 5 seconds the backend commits and closes anyway.
- **Conflict handling:** "Keep my version" commits the on-disk (external) version first, then writes yours. "Load disk version" commits the external version, writes and commits your unsaved text, then restores the disk version, so both stay in history.
- **UI-only state** (selected tab, dialogs, toasts) lives in `uiStore`; panel sizes are persisted through a try/catch `localStorage` wrapper.
- **`src/bindings/` is committed** (generated by `pnpm bindings`) so the frontend builds and tests without a Rust toolchain.
- Prettier ignores `CLAUDE.md` (the specification must not be reformatted).

## v2 features (chat history, templates, tabs, tables, export, semantic search)

| Decision                                                                                                                                                            | Reason                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| New dependencies: `docx-rs` 0.4 (Word export), `base64` 0.23 (HTML image embedding), `zip` (dev only, reads .docx in tests)                                         | Word files need a writer; base64 encodes images; zip lets tests check the .docx. No other crates.                        |
| Tables are shown as widgets outside the cursor; **Tab on a raw table does not auto-format**                                                                         | Plan item 6.6b was optional; the widget covers the main use.                                                             |

| Layout restore is read before the workspace is reset, and saving is paused during resets                                                                            | Otherwise the empty initial layout would overwrite the saved tabs.                                                       |
| `save_template` / `create_note_from_template` use `resolve_internal` for `.vault/templates/`                                                                        | `.vault` is refused by the normal path rules; templates live there on purpose.                                           |
| `VaultConfig` gained daily-note fields with defaults                                                                                                                | Old `config.json` files still load (tested).                                                                             |
| Chats have `projectId: null` in v2                                                                                                                                  | Project tagging was not in the plan's required fields; can be added later without a format change.                       |
| Word export: lists use text markers (•, 1.) instead of Word numbering; frontmatter properties are shown from simple `key: value` lines (not parsed with yaml-rust2) | Keeps the writer small; the plan allowed this limitation.                                                                |
| PDF export: the app shows an HTML print preview and calls the system print dialog                                                                                   | No PDF engine dependency; the user chooses "Save as PDF" in the dialog.                                                  |
| Export HTML: raw HTML in notes is escaped; links limited to http(s), mailto and in-document anchors; images from the vault only, max 10 MB                          | Notes are untrusted text; the output must never run scripts.                                                             |
| Semantic search stores vectors in `.vault/embeddings.db` (gitignored), brute-force cosine search over an in-memory cache                                            | Simple and fast enough for the 1 000–5 000 note range; avoids a vector database.                                         |
| Semantic index restarts (cancelling the running job) on every file change instead of a 10 s debounce                                                                | Simpler; the job skips unchanged notes quickly. Can be debounced later if it proves costly.                              |
| The assistant's semantic tool is offered only when allowed (enabled, indexed, and a local embedding provider); the citation prompt rule was not added               | The rule that matters (no cloud use for local-only projects) is enforced in code and tested.                             |
| `hybrid_search` uses reciprocal rank fusion (k = 60)                                                                                                                | No tuning needed; the plan specified it.                                                                                 |

| Decision                                                                                                                                            | Reason                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
